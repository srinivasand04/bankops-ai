BankOps AI

Banking IT incident intelligence: track incidents through a controlled lifecycle, let an AI investigate them from cited evidence, and keep a human in charge of every decision.

30-second pitch

When a bank's payment system fails, engineers spend the first hour collecting logs, metrics and recent changes before anyone can say what broke. BankOps AI does that collection automatically: it builds a fact base where every log line, metric and change has an ID, asks a language model for root-cause hypotheses that must cite those IDs, and checks every citation before a human incident manager approves or rejects the result. The AI never confirms a root cause or closes an incident itself, which is how a regulated bank has to work.

System architecture

One incident, end to end

  1. Release CHG-2041 ships; 30 minutes later monitoring raises INC-1007 (P1, Payment Processing).
  2. The state machine only allows valid steps (assign, investigate, escalate, resolve); each one is written to an audit timeline, and SLA clocks run against the targets.
  3. An engineer clicks Analyse with AI. The backend gathers the incident, its timeline, dependent applications, recent changes and metrics into a fact base with IDs such as EV-33 and MS-PAY-http_5xx_rate_pct.
  4. The model returns structured JSON: summary, cited facts, ranked hypotheses with confidence, impact and actions. It runs in the background while the page refreshes.
  5. Guardrails strip citations that do not exist, demote uncited "facts", and force approval on anything that changes production, such as a rollback.
  6. An incident manager approves or rejects it (an engineer's attempt is refused by the API), then confirms the right root cause.

How the AI is kept honest

Evidence first

The model only sees a fact base from the database. Every claimed fact must cite an ID that exists; others are removed and listed.

Hypotheses, not answers

AI root causes are always stored as hypotheses. A database constraint and the API make confirmation a human-only step.

Recommend, never act

Rollbacks, restarts and config changes are forced to "needs approval". The AI identity cannot close incidents or approve its own work.

Reviewed and audited

Every step is on an append-only timeline marked HUMAN, AI or SYSTEM. Rejected analyses change nothing.

Deploy it online for free

  1. Push the code: git add -A, git commit -m "Deploy config", git push.
  2. Groq (console.groq.com): create an API key.
  3. Neon (neon.tech): new project, copy the connection string.
  4. Render (render.com): New → Blueprint → pick the repo (it reads render.yaml); paste DATABASE_URL, GROQ_API_KEY and CORS_ORIGINS = ["*"] for now.
  5. Vercel (vercel.com): Add New → Project → the repo, root folder frontend, variable VITE_API_BASE_URL = https://bankops-ai-api.onrender.com/api.
  6. Put the Vercel address in Render's CORS_ORIGINS, e.g. ["https://bankops-ai.vercel.app"].

Questions you may get

How do you stop the model from hallucinating?

It only sees database facts with IDs, and must cite them. The backend checks every citation; anything uncited is moved out of "facts". Root causes stay hypotheses until a human confirms one.

Did the AI ever get it wrong?

Yes. A small local model blamed a healthy Core Banking system for a reporting delay, although its metrics were flat. The reviewer rejected it, which is exactly why the human step exists. On four test incidents it was right three times.

Why three LLM providers?

Claude gives the best reasoning, Groq is free and fast for a public demo, and Ollama keeps data on the machine, which matters for banks. Switching is one setting because everything uses one interface.

How do you test AI features without paying for tokens?

The LLM is a dependency, so tests swap in a fake that returns a deliberately imperfect answer and check each guardrail. A mocked SDK checks the exact request. 161 tests run in under a minute.

Why not let the AI roll back a bad release?

Bank change management requires an authorised human, often an emergency CAB. The AI recommends and explains; the API refuses consequential actions from an AI identity.
